= Install the OpenStack Operator (RHOSO 19.0 beta)

[IMPORTANT]
====
This track installs the *RHOSO 19.0 beta* build. The beta is not published on
`registry.redhat.io`, so it is consumed from a mirror in `quay.io/redhat_emp1`:

* catalog index — `quay.io/redhat_emp1/pnavarro-rhoso19-beta-index:latest`
* operator and service images — `quay.io/redhat_emp1/pnavarro-rhoso19-beta/<image>`

Two cluster-wide objects make this work: a *CatalogSource* so OLM can see the
beta operator, and an *ImageDigestMirrorSet* so the nodes fetch every
`registry.redhat.io/rhoso*` image from quay instead.
====

. Clone the Files Repo
+
In the bastion terminal, clone the repo and change directory to the files that we will used later in the lab
+
[source,bash,role=execute]
----
git clone https://github.com/rhpds/osp-on-ocp-showroom.git labrepo
cd labrepo/content/files
----

== Give the cluster access to the beta images

. If the quay repositories are *private*, store your quay credentials in the
cluster-wide pull secret so every node can fetch the beta images. Skip this step
if the repositories have been made public:
+
[source,bash,role=execute]
----
oc get secret/pull-secret -n openshift-config \
  --template='{{index .data ".dockerconfigjson" | base64decode}}' > /tmp/pull-secret.json

oc registry login --registry=quay.io \
  --auth-basic=<quay-user>:<quay-token> \
  --to=/tmp/pull-secret.json

oc set data secret/pull-secret -n openshift-config \
  --from-file=.dockerconfigjson=/tmp/pull-secret.json

rm -f /tmp/pull-secret.json
----
+
[NOTE]
Updating the cluster-wide pull secret rolls the nodes through the Machine Config
Operator. Wait for `oc get mcp` to report `UPDATED=True` before continuing.

. Apply the *ImageDigestMirrorSet* so that every `registry.redhat.io/rhoso*`
image resolves to the quay mirror:
+
[source,bash,role=execute]
----
oc apply -f osp-ng-rhoso19-beta-idms.yaml
----
+
This rewrites `/etc/containers/registries.conf` on each node and restarts them
one at a time. Follow the rollout and wait until it finishes:
+
[source,bash,role=execute]
----
oc get mcp -w
----
+
Type Control + C once both pools report `UPDATED=True` and `UPDATING=False`.

. Add the beta *CatalogSource*:
+
[source,bash,role=execute]
----
oc apply -f osp-ng-rhoso19-beta-catalogsource.yaml
----

. Confirm the catalog pod is running and the operator is on offer:
+
[source,bash,role=execute]
----
oc get pods -n openshift-marketplace -l olm.catalogSource=rhoso19-beta
oc get packagemanifests -n openshift-marketplace | grep openstack-operator
----
+
.Sample Output
----
NAME                            CATALOG            AGE
openstack-operator              RHOSO 19.0 beta    30s
----
+
[NOTE]
If the catalog pod is in `ImagePullBackOff`, the quay repositories are private
and the cluster has no credentials for them. Either make them public or create a
pull secret in `openshift-marketplace` and reference it under `spec.secrets` in
*osp-ng-rhoso19-beta-catalogsource.yaml*.

== Install the operator

. Create the *openstack-operators* project for the RHOSO operators:
+
[source,bash,role=execute]
----
oc new-project openstack-operators
----

. Create the `openstack` project for the deployed RHOSO environment:
+
[source,bash,role=execute]
----
oc new-project openstack
----

. Configure the **OperatorGroup and Subscription** for the **OpenStack Operator**
from **files/osp-ng-openstack-operator-19beta.yaml**. It subscribes to channel
*beta-v19.0* from the *rhoso19-beta* catalog:
+
[source,bash,role=execute]
----
oc apply -f osp-ng-openstack-operator-19beta.yaml
----

. Install the operator using the Manual approval strategy. Confirm that an install plan has been created but not executed as it has not been approved. Type Control + C, to exit the wait command:
+
[source,bash,role=execute]
----
oc get installplan -n openstack-operators -w
----
.Sample Output
----
NAME            CSV                          APPROVAL   APPROVED
install-lfs4j   openstack-operator.v19.0.0   Manual     false
----

. Approve the installation of the operator by updating the approved field of the InstallPlan. You will need to replace <install-plan-id> with the NAME from the previous command:
+
[source,bash,role=execute]
----
oc patch installplan <install-plan-id>  \
    --namespace openstack-operators \
    --type merge \
    --patch '{"spec":{"approved":true}}'
----

. Initialize the operator:
+
[source,bash,role=execute]
----
oc apply -f osp-ng-openstack-operator-init.yaml
----

. Confirm that you have installed the Openstack Operator, *openstack-operator.openstack-operators*:
+
[source,bash,role=execute]
----
oc get operators openstack-operator.openstack-operators
----

. Check that the CSV reports version *19.0.0*:
+
[source,bash,role=execute]
----
oc get csv -n openstack-operators -o custom-columns=Name:.metadata.name,Version:.spec.version,Phase:.status.phase
----
+
.Sample Output
----
Name                         Version   Phase
openstack-operator.v19.0.0   19.0.0    Succeeded
----

. Review the pods in the **openstack-operators** namespace:
+
[source,bash,role=execute]
----
oc get pods -n openstack-operators
----

[source, bash,role=execute]

. If a controller pod is stuck in `ImagePullBackOff`, the mirror is not resolving.
Check which image it wants and confirm the mapping exists in the IDMS:
+
[source,bash,role=execute]
----
oc describe pod -n openstack-operators <pod-name> | grep -A2 "Failed to pull"
oc get imagedigestmirrorset rhoso19-beta-quay -o yaml | grep -A2 <image-name>
----
