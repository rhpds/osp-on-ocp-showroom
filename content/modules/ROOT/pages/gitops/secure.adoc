= Prepare RHOSO secrets with Validated Patterns

This chapter prepares every Secret used during the connected RHOSO installation
(`osp-secret`, `libvirt-secret`, `cinder-nfs-config`, dataplane SSH keys,
subscription manager, and Red Hat registry) by filling a local
`values-secret.yaml` file and loading it with the Validated Patterns framework.

== 1. Enable the secrets loader (Kubernetes backend)

This lab uses the **kubernetes** secrets backend: Validated Patterns writes
Secrets into `validated-patterns-secrets`, and External Secrets Operator
projects them into `openstack`. That matches the
https://validatedpatterns.io/learn/secrets-management-in-the-validated-patterns-framework/#secrets-backends-in-the-validated-patterns-framework[Validated Patterns kubernetes backend^].

On the bastion, in your forked pattern repository:

[source,bash,role=execute]
----
cd /home/lab-user/rhoso-gitops
----

Edit `values-global.yaml` so secret loading is enabled and the backend is
`kubernetes`:

[source,bash,role=execute]
----
cat > values-global.yaml <<'EOF'
---
global:
  pattern: rhoso-gitops
  secretLoader:
    disabled: false
  secretStore:
    backend: none
  options:
    useCSV: false
    syncPolicy: Automatic
    installPlanApproval: Automatic
main:
  clusterGroupName: standalone
  multiSourceConfig:
    enabled: true
    clusterGroupChartVersion: "0.9.*"
EOF
----

[NOTE]
Do not commit a filled `values-secret.yaml`. The pattern `.gitignore` already
excludes `values-secret.yaml`. You may commit the `values-global.yaml` change
above (it contains no secret material).

== 3. Create your local `values-secret.yaml`

The pattern ships an empty template at `values-secret.yaml.template`. The loader
searches for a secrets file in this order and uses the first match:

. `~/.config/hybrid-cloud-patterns/values-secret-rhoso-gitops.yaml`
. `~/.config/validated-patterns/values-secret-rhoso-gitops.yaml`
. `~/values-secret-rhoso-gitops.yaml`
. `~/values-secret.yaml`
. `{{ pattern_dir }}/values-secret.yaml.template`

For this lab, copy the template next to the pattern and fill it in:

[source,bash,role=execute]
----
cd /home/lab-user/rhoso-gitops
cp values-secret.yaml.template ~/values-secret.yaml
----

Write the secrets file. Demo control-plane passwords match the connected lab
files (`openstack`). Replace the Red Hat credential placeholders with your own
values.

[IMPORTANT]
Add your username and password from the
https://www.redhat.com/wapps/ugc/protected/password.html[Red Hat Customer Portal^]
for `subscription-manager`, and a
https://access.redhat.com/articles/RegistryAuthentication#creating-registry-service-accounts-6[Registry Service Account^]
token for `redhat-registry`.

documentation. Optionally encrypt the file at rest with
`ansible-vault encrypt ~/values-secret-rhoso-gitops.yaml`.
====

== 4. Load secrets onto the cluster

Ensure the bootstrap namespace exists, then run the pattern secrets loader:

[source,bash,role=execute]
----
oc create namespace validated-patterns-secrets --dry-run=client -o yaml | oc apply -f -
cd /home/lab-user/rhoso-gitops
./pattern.sh make load-secrets
----

If the secrets file is encrypted with Ansible Vault, the loader prompts for the
vault password.

Confirm the source Secrets were created:

[source,bash,role=execute]
----
oc get secret -n validated-patterns-secrets
----

Expected names:

----
osp-secret
libvirt-secret
cinder-nfs-config
dataplane-ansible-ssh-private-key-secret
nova-migration-ssh-key
subscription-manager
redhat-registry
----

[NOTE]
These Secrets exist only in `validated-patterns-secrets` until External Secrets
copies them into `openstack`.

== Create the `openstack-secrets` Git overlay

Create store wiring and ExternalSecrets in Git.
Argo applies them after ESO CRDs exist (retries handle the wait).

[source,bash,role=execute]
----
cd /home/lab-user/labrepo
mkdir -p gitops/environments/demo-env/secrets

=== Kustomization

[source,bash,role=execute]
----

kind: Kustomization

----

=== ExternalSecret manifests

With the Kubernetes provider, `dataFrom.extract.key` is the **name of the source
Secret** in `validated-patterns-secrets` (not a Vault path).

[source,bash,role=execute]
----
cat > gitops/environments/demo-env/secrets/externalsecret-osp-secret.yaml <<EOF
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: osp-secret
  namespace: openstack
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: kubernetes-secretstore
    kind: ClusterSecretStore
  target:
    name: osp-secret
    creationPolicy: Owner
  dataFrom:
    - extract:
        key: osp-secret
EOF
----

=== Add External Secrets Operator to the operator dependencies section in the values-rhoso-gitops.yaml file

On the bastion, in your forked pattern repository:

[source,bash,role=execute]
----
cd /home/lab-user/rhoso-gitops
----

Edit `overrides/values-rhoso-gitops.yaml` so `operator-dependencies` includes the
community ESO component (and Argo annotations for CRD dry-run behaviour).

[source,bash,role=execute]
----
vim overrides/values-rhoso-gitops.yaml
----

Replace the existing `operator-dependencies` block with:

[source,yaml]
----
  operator-dependencies:
    enabled: true
    repoURL: https://github.com/openstack-k8s-operators/gitops
    path: example/dependencies
    targetRevision: v0.3.1
    kustomize:
      components:
        - "https://github.com/openstack-k8s-operators/gitops/components/secrets/external-secrets-operator/redhat?ref=v0.3.1"
        - "https://github.com/openstack-k8s-operators/gitops/components/argocd/hooks/postDelete/deploy-operators?ref=v0.3.1"
        - "https://github.com/openstack-k8s-operators/gitops/components/dependencies/provisioning-config?ref=v0.3.1"
        - "https://github.com/openstack-k8s-operators/gitops/components/argocd/annotations?ref=v0.3.1"
    syncPolicy:
      automated: {}
      retry:
        limit: 5
        backoff:
          duration: 30s
          factor: 2
          maxDuration: 3m
      syncOptions:
        - Prune=true
        - SkipDryRunOnMissingResource=true
----

== Configure the secrets validated patterns section in the values-rhoso-gitops.yaml file

On the bastion, in your forked pattern repository:

[source,bash,role=execute]
----
cd /home/lab-user/rhoso-gitops
----

Edit `overrides/values-rhoso-gitops.yaml` so `secrets` includes the
secrets environment overlay.

[source,bash,role=execute]
----
vim overrides/values-rhoso-gitops.yaml
----

Replace the existing `secrets` block with:

WARNING: Replace $your_github_id with your GitHub ID.

[source,yaml]
----
  openstack-secrets:
    enabled: true
    repoURL: https://github.com/$your_github_id/rhoso-gitops
    path: gitops/environments/demo-env/secrets
    targetRevision: main
    syncPolicy:
      automated: {}
      retry:
        limit: 5
        backoff:
          duration: 30s
          factor: 2
          maxDuration: 3m
      syncOptions:
        - Prune=true
        - SkipDryRunOnMissingResource=true
----

Commit the files created and push them to your GitHub repo:

[source,bash,role=execute]
----
git add overrides/values-rhoso-gitops.yaml
git commit -m "Configure ESO and secrets validated patterns section in the values-rhoso-gitops.yaml file"
git push origin
----
