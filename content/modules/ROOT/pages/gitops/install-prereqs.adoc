== Login to the preprovisioned Compute and configure networking

From the bastion login to the *compute01* host:

[source,bash,role=execute,subs=attributes]
----
ssh -i /home/lab-user/.ssh/{guid}key.pem cloud-user@compute01
----

[source,bash,role=execute,subs=attributes]
----
sudo hostnamectl set-hostname edpm-compute-1.sandbox-{guid}-ocp4-cluster.svc.cluster.local
sudo nmcli con add con-name "static-eth1" ifname eth1 type ethernet ip4 172.22.0.100/24 ipv4.dns "172.22.0.89"
sudo nmcli con up "static-eth1"
sudo nmcli con add type ethernet ifname eth0 con-name eth0-dhcp ipv4.method auto ipv6.method ignore
sudo nmcli con up eth0-dhcp
sudo nmcli con mod eth0-dhcp connection.stable-id "user-set"
----

And log off VM

[source,bash,role=execute]
----
logout
----

== Install kustomize

In the bastion, execute:

[source,bash,role=execute]
----
wget https://github.com/kubernetes-sigs/kustomize/releases/download/kustomize%2Fv5.6.0/kustomize_v5.6.0_linux_amd64.tar.gz
tar -xvzf kustomize_v5.6.0_linux_amd64.tar.gz
sudo cp kustomize /usr/local/bin/.
----

== Allow the pattern Argo CD instance to manage cluster-scoped resources

Validated Patterns deploys the RHOSO applications through the cluster (hub) Argo
CD instance in the `openshift-gitops` namespace. That instance must remain
cluster-scoped so child applications can create cluster-level resources
(CRDs, ClusterRoles, OperatorGroups, and so on). The Validated Patterns
`imperative` namespace also needs cluster scope for helper Jobs.

Without this setting, applications can fail with errors like
`can not be managed when in namespaced mode`, and the OpenStack operator never
installs.

NOTE: The AppProject name `rhoso-gitops-standalone` is only a Validated Patterns
*clusterGroup* / project label. This lab does **not** create a second Argo CD
instance or a `rhoso-gitops-standalone` namespace.

Patch the GitOps Operator Subscription so `openshift-gitops` and `imperative`
are treated as cluster-scoped:

[source,bash,role=execute]
----
oc patch subscription openshift-gitops-operator -n openshift-operators --type=merge -p '{
  "spec": {
    "config": {
      "env": [
        {
          "name": "ARGOCD_CLUSTER_CONFIG_NAMESPACES",
          "value": "openshift-gitops,imperative"
        }
      ]
    }
  }
}'
----

Wait until the operator deployment picks up the new environment variable:

[source,bash,role=execute]
----
oc set env deployment/openshift-gitops-operator-controller-manager \
  -n openshift-operators --list | grep ARGOCD_CLUSTER_CONFIG_NAMESPACES
----

The output must include `openshift-gitops` and `imperative`. If the variable is
missing or incomplete, restart the operator deployment and check again:

[source,bash,role=execute]
----
oc rollout restart deployment/openshift-gitops-operator-controller-manager \
  -n openshift-operators
oc rollout status deployment/openshift-gitops-operator-controller-manager \
  -n openshift-operators
----
