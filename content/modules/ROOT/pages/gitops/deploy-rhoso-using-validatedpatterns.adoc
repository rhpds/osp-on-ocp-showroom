= Deploy RHOSO using Validated Patterns.

== Make sure you don't have any pending git commits in the repository

=== Lab repository

[source,bash,role=execute]
----
cd /home/lab-user/labrepo
git status
----
If you have any pending git commits, you need to commit them before continuing.
[source,bash,role=execute]
----
git add .
git commit -m "Final commit to update the lab repository"
----

Push the changes to the lab repository:
[source,bash,role=execute]
----
git push origin
----

== Access the pattern Argo CD console to verify the deployment

The pattern deploys RHOSO through the standalone Argo CD instance in
`rhoso-gitops-standalone`. Use that console to watch child applications such as
`operator-dependencies`, `openstack-operator`, and `openstack-controlplane`.

Extract the admin password:

[source,bash,role=execute]
----
argoPass=$(oc get secret/standalone-gitops-cluster -n rhoso-gitops-standalone -o jsonpath='{.data.admin\.password}' | base64 -d)
echo $argoPass
----

Get the Route for the standalone GitOps server:

[source,bash,role=execute]
----
argoURL=$(oc get route standalone-gitops-server -n rhoso-gitops-standalone -o jsonpath='{.spec.host}{"\n"}')
echo $argoURL
----

Confirm the applications are syncing:

[source,bash,role=execute]
----
oc get applications -n rhoso-gitops-standalone
----

If an application reports `can not be managed when in namespaced mode`, return
to xref:install-prereqs.adoc[the GitOps Operator cluster-scope prerequisite]
and verify `ARGOCD_CLUSTER_CONFIG_NAMESPACES` includes `rhoso-gitops-standalone`.
