= Deploy RHOSO using Validated Patterns.

== Make sure you don't have any pending git commits in the repository

=== Lab repository

[source,bash,role=execute]
----
cd /home/lab-user/labrepo
git status
----
If you have any pending git commits, you need to commit them before continuing.
[source,bash,role=execute]
----
git add .
git commit -m "Final commit to update the lab repository"
----

Push the changes to the lab repository:
[source,bash,role=execute]
----
git push origin
----

----

== Access the pattern Argo CD console to verify the deployment

Validated Patterns installs the RHOSO applications into the cluster (hub) Argo CD
instance in the `openshift-gitops` namespace. Use that console to watch child
applications such as `operator-dependencies`, `openstack-operator`, and
`openstack-controlplane`.

NOTE: The AppProject name `rhoso-gitops-standalone` refers to the Validated
Patterns *clusterGroup*, not a separate Argo CD namespace. On this lab there is
no `rhoso-gitops-standalone` namespace and no `standalone-gitops` Argo CD
instance.

Extract the admin password:

[source,bash,role=execute]
----
argoPass=$(oc get secret/openshift-gitops-cluster -n openshift-gitops -o jsonpath='{.data.admin\.password}' | base64 -d)
echo $argoPass
----

Get the Route for the GitOps server:

[source,bash,role=execute]
----
argoURL=$(oc get route openshift-gitops-server -n openshift-gitops -o jsonpath='{.spec.host}{"\n"}')
echo $argoURL
----

Open `https://$argoURL` in a browser and log in as `admin` with the password
from the previous step.

Confirm the applications are syncing:

[source,bash,role=execute]
----
oc get applications -n openshift-gitops
----

If an application reports `can not be managed when in namespaced mode`, return
to xref:install-prereqs.adoc[the GitOps Operator cluster-scope prerequisite]
and verify `ARGOCD_CLUSTER_CONFIG_NAMESPACES` includes `openshift-gitops`.
